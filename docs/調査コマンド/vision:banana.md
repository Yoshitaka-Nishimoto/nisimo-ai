> /vision:banana --help                                                                                                                      
✦ ご提示いただいたテキストは、Gemini CLIにおける `/vision:banana` コマンドの内部的な動作定義（スクリプトの設計書） そのものです。


  この内容から、/vision:banana コマンドが裏側でどのような処理を順番に行っているかが明確に分かります。一つずつ日本語で解説します。

  /vision:banana コマンドの動作フロー


  1. カメラの確認 (`vision_status`)
   * まずカメラが開いているかチェックします。
   * 開いていない場合は、「Camera closed — run /vision:start（カメラが閉じています。/vision:start を実行してください）」とエラーを出して停止します。


  2. 引数（オプション）の解析
  以下の設定値（オプション）を受け取ります。指定がない場合はカッコ内のデフォルト値が使われます。
   * prompt: 画像生成の指示文（デフォルト: "Create a refined, cinematic re-imagination of this photo." =
     この写真の洗練された映画のような再構築画像を作成してください）
   * out_dir: 保存先フォルダ（デフォルト: . = 現在のフォルダ）
   * format: 撮影する写真の形式（デフォルト: jpg、pngも可）
   * model: 使用するAIモデル（デフォルト: gemini-2.5-flash-image-preview）
   * n: 生成する画像の枚数（デフォルト: 1枚）
   * outfile_base: 撮影した元写真に分かりやすい名前を付けてコピー・保存するためのオプション設定


  3. 写真の撮影 (`vision_capture`)
   * ウェブカメラを使って現在の風景（またはあなた）を1枚撮影し、指定したフォルダに保存します。


  4. ファイル名の変更（オプション）
   * outfile_base が指定されていれば、撮影した写真のファイル名を指定された名前にコピー・変更します。


  5. AIによる画像生成 (`banana_generate`)
   * ここがメインの処理です。
   * 手順3で撮影した「写真」と、手順2の「プロンプト（指示文）」をセットにしてAIモデル（Geminiの画像生成モデル）に送信します。
   * AIがプロンプトに従って写真を変換・生成し、新しい画像として保存します。


  6. 結果の出力
   * ターミナル上に、以下のような結果を表示します。
       * Captured: [撮影した元写真のパス]
       * Saved: [AIが生成した画像のパス]
   * 同時に、生成された画像ファイルをその後のチャットで参照しやすいように @ファイル名 の形式でアタッチ（添付）します。

  ---


  つまりどういうことか？
  /vision:banana
  は、単に絵を描くコマンドではなく、「ウェブカメラで今すぐ写真を撮り、それを下敷きにして（Image-to-Imageで）、AIにイラストや別スタイルの画像を即座に描かせる」た
  めの一連の自動化マクロ（ツールチェイン）として定義されていることがわかります。
